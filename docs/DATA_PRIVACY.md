# 数据与隐私设计

本文件主要描述后续持久化阶段的实现要求。当前 M1 已有本地运行的聊天服务：在内存中保留最近 12 轮会话，重启即丢失；API 模式会把近期对话发送到所选供应商，尚未实现长期记忆、独立情绪分析或下表中的持久化保留策略。Gemini 真实验证使用合成经历；密钥仅在本地配置，由后端读取。详见 [当前架构](ARCHITECTURE.md)。

## 玩家控制

- 首次使用解释模型、记忆和外部工具会处理哪些信息；长期记忆默认关闭，由玩家主动开启。
- 情绪分析提供独立开关和说明；不开启时不调用专门情绪分析流程。
- 玩家主动提供城市，默认城市级精度；临时天气查询地点不自动覆盖常住城市。
- 健康、创伤等敏感经历不默认长期保存；确有需要时逐条确认。
- 支持单条纠正、删除、清空记忆和完整账户删除；关闭记忆不等同于删除已有数据，界面必须明确区分。

## 数据生命周期

| 数据 | 拟议保留策略 |
| --- | --- |
| 原始对话 | 玩家可删除；初版默认保留 30 天，部署前明确说明 |
| 已授权长期记忆 | 玩家可管理；事件过期后降权或归档，删除前不假设永久有效 |
| 情绪估计 | 默认临时处理，最长 24 小时；不作为永久人格标签 |
| 天气缓存 | 建议 15 分钟，具体按供应商能力与时间类型配置 |
| 运行日志 | 默认 14 天，仅保留脱敏技术信息 |
| 备份 | 拟定最长 30 天滚动过期，恢复时必须重新应用删除记录 |

以上是产品默认方案，需在实际部署配置及界面中同步，不属于已实现承诺。

删除操作应立即撤销检索资格，清理事实、嵌入、摘要与缓存，并使未完成写入失效。单条记忆删除后，保留的历史聊天不得自动重建同一记忆；使用不含原文的来源撤销标记和任务版本检查。若玩家要求移除原始表达，提供对应聊天删除入口。账户删除清理全部关联数据，备份按明确周期过期。

## 隔离与外部服务

身份由服务端认证获取，查询与写入均检查所有权。不同玩家与角色之间默认隔离。发送给模型的内容遵循最小必要原则；天气供应商仅接收城市及查询时间，不接收聊天与情绪历史。真实模型接入前核验数据保留、训练使用、所在区域与退出选项，向玩家说明。

## 开源仓库

只允许原创或授权角色设定、合成数据和不含秘密的配置模板。禁止提交真实聊天、定位、记忆导出、数据库、日志、API 密钥和 `.env`。公开测试报告使用合成案例或获得明确公开授权的数据。若后续面向未成年人或特定地区上线，再依据实际范围审查相应要求。
