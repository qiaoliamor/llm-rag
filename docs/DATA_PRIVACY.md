# 数据与隐私边界

[中文](DATA_PRIVACY.md) · [日本語](ja/DATA_PRIVACY.md)

更新日期：2026-11-10（Asia/Tokyo）。本文件区分已经实现的本地行为与未来发布要求。

## 当前已实现

记忆/天气/情绪分别需30/60/90分资格且独立授权；解锁不自动授权，锁定仍可查看/删除已有资料及撤回。账户联系方式不进入Prompt/记忆，清空联系方式不清钱包/流水/分数。钱包仅演示币，不收真钱；完整账户注销/经济流水留存尚未实现。

- 完整聊天仅在服务内存中保留最近12轮，重启清除；数据库不保存完整聊天日志。
- 长期记忆默认关闭。开启后本轮明确表达的重要信息可形成候选，所有候选逐条确认；不把推测心情写为长期标签。敏感经历也不会自动确认。
- 候选包含用户提供的事实摘录，最多300字符，以及来源消息ID、时间、状态、类别、日期、规则默认重要度/置信度与版本；确认事实及向量保存在本机。
- 页面可查看、手动添加、纠正、确认、单条或全部删除，关闭后不再检索/提取，仍可删除；关闭不等于清空。
- 随机持久化身份 Cookie 归属本浏览器，数据库保存 token 指纹；不是跨设备账号。清除 Cookie 后没有自动身份恢复功能。其他身份或角色不能访问这些记忆。
- 候选24小时后在访问/提取时清理。面试/考试/手术等预约到日期后31天不参与检索但仍可查看删除；重要历史经历及偏好保留至玩家删除。复杂日期不补写。
- API 仅向当前供应商发送角色约束、近期对话、本轮消息和检索命中的有效确认记忆。特征向量本地计算，不向嵌入服务额外发送事实。M3天气供应商仅接收城市名/城市id或坐标和时区，M4额外情绪分析复用当前模型，只在独立授权后发送有限聊天窗口。

## 天气设置与外部数据流

中日semantic天气理解在60分资格及独立授权之后，将本轮聊天原文及有效待澄清日期结构发送给当前对话模型；不附长期记忆、账户、助手历史、保存城市。不确定/失败不查天气。城市/日期原文绑定和字符校验不能证明模型语义判断完全正确。新增设置说明中日同步；legacy仅明确历史回放。

天气授权独立且默认关闭；主动城市搜索会向Open-Meteo/GeoNames发送城市查询，天气查询只发送坐标/时区，不发送完整聊天或记忆，不读IP/GPS。必要天气事实（包括可用当前湿度）会与相关确认记忆一起传给当前对话模型，来源/获取与有效时间等元数据另给UI显示。成功回复的天气快照随短期历史在内存保留，刷新可恢复；发送给模型的历史只含role/content，不附带历史天气元数据。数据不是匿名访问：天气服务仍能看到查询地点和服务器IP。

`weather_profiles` 在本地保存身份、授权和所选城市必要字段。临时目的地不写常用城市，天气结果只保存在进程公共缓存（600秒、最多128条，无身份键）。删除设置物理移除该身份行并关闭查询，清空短期历史、使旧回复失效，同时清空公共缓存；在途公共请求可重新填入无身份的天气，但不会恢复设置。关闭后不再查询；保留还是移除城市取决于保存时选定的city_id，删除按钮始终移除。细节见 [天气设计](WEATHER.md)。

## 情绪参考与授权

情绪回复审查仍复用当前模型，不新增供应商；只投影必要标签/来源/置信/basis或估计强度，去掉情绪原始证据ID/observed_at和自述强度占位。当前语言/有效陪伴偏好/状态单列emotion_policy，不得当心理事实证据；关闭时不发送旧参考。没有新增情绪资料持久化或长期记忆写入，原权限与epoch失效流程不变。

默认semantic在90分且独立授权后**每轮**发送本轮原文/ID、有限短期窗口与现参考标签/来源，先理解自述及触发；完整估计仍按间隔/冷却执行，两步共用6秒默认预算且不重试。原文引用只用于本地校验、不作为新持久化资料；模型解释的自述source=model+basis=self_report，source=user仅手动纠正。本轮陪伴偏好不写设置；失败不注入旧模型结果，原手动纠正可保留供查看。窗口本身可能含玩家主动写下的事实，不额外读取账户/长期库或工具快照。详见[情绪语义设计](EMOTION.md)。

情绪分析独立默认关闭，开启会额外向当前Gemini/OpenAI发送最近指定轮数的聊天文本；不发送完整记忆库或API密钥，但聊天中已经提及的事实仍在窗口里。emotion_profiles只持久化授权、频率、窗口、冷却、阈值及玩家明确偏好，推测标签/强度/分析原文不落盘、不直接写长期记忆。

临时推测/纠正在当前会话10分钟或6轮内使用，访问时判失效，无后台定时擦除。新对话、纠正、清空、关闭/删除设置清除临时参考及短期聊天；删除设置物理移除配置，清空推测仅保留配置。epoch撤销旧回复且不抹去更新的玩家纠正；跨设备和完整账户删除仍待后续。详见 [情绪设计](EMOTION.md)。

## 删除与纠正

删除物理移除事实原文及向量，不保留文本修订副本。保留动作/版本元数据与用户盐内容指纹，防止已删除句子被自动重新提取；指纹不是加密或彻底匿名化。玩家显式手动重新添加并确认属于重新授权。

纠正、确认、删除及设置变更增加身份的 epoch，并清空相关短期历史。生成过程中发生撤回，旧回复不返回；旧 epoch 的候选写入被拒绝。其他进程在下一次请求检查 epoch。其他窗口已经显示的旧消息需刷新才能消失。

当前没有外部记忆缓存或后台提取队列。数据库可见范围、版本和事务共同约束修改；不宣称已经实现云备份擦除或生产账户注销。

## 本地保存与秘密

PostgreSQL/pgvector 使用专用 Docker 卷，仅绑定127.0.0.1:54329；凭据由初始化脚本生成到本地 `.env`，权限600。SQLite 备用文件位于忽略的 data/，文件权限600。数据库不提供应用级加密，磁盘/容器卷权限和设备安全仍重要。

`.env`、数据库、卷内容、运行日志、依赖和构建产物不提交。开源只包含代码、空配置、文档、schema与合成测试。版本报告只记录合成测试结论，不上传真实用户对话和原始运行导出。

Gemini 免费档的数据使用条件需以供应商与项目实际配置为准；调用成功不证明免费额度或训练退出设置。OpenAI 适配使用 store=False，也不能据此声称所有供应商日志均不保留。

## 语义记忆的新增数据流

memory_understanding_mode=semantic且已解锁/授权时，每轮的原文、最多最近12条短期消息、用户时区和当地日期会发给当前模型，先判断是否需要旧记忆；不先读库。真正需要时，再将本人可见且已确认/未过期的最多20条字符召回候选的id/fact/event_date发给同一供应商语义选择；最终最多5条/1200字符进入生成。不是把全部记忆库直接发送，也不是“每轮一定查库”。

手动添加/修正也会发送这段原文解析元数据，确认时原文不变则不额外分析；界面已说明。理解结果只作为当前请求临时数据；仅通过源引用/结构校验的候选原文和既有字段元数据在成功回复后保存，全部仍待逐条确认。失败不重试或正则补猜，手动原文可保存但日期未知。关闭/未解锁阻止调用，epoch撤回阻止在途旧结果写入；不能据此保证供应商擦除已接收内容。旧embedding仍本地，不新增嵌入供应商。

默认回复semantic会将自由回复、既有必要用户上下文、正史/场景、已选确认记忆和本轮工具参考发送给同一配置模型审查（完整可信短句在无其他核对要求时免审查）；不额外检索记忆、不改变解锁或授权。reply_policy仅locale，不能证明人物事实；助手历史只供虚构连续性，不升为玩家事实。不增加存储、日志、表或第三方；调用频率可能增加，真实成本未验收。
