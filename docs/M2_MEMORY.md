# M2 · 长期记忆与按需检索

[中文](M2_MEMORY.md) · [日本語](ja/M2_MEMORY.md)

状态：候选确认、跨会话记忆及网页管理已实现；“M2完成”仅指功能闭环。M5检索/来源时间修复已交付，质量泛化仍待验收。

## 功能与生命周期

1. 亲密度30获得资格，玩家另行授权后才提取/检索；关闭不删除，查看/删除和撤回始终可用。
2. 只从玩家明确表达的重要事实/偏好/事件保守提取候选，也支持手动添加；逐条确认后才参加检索，不把推测心情自动存为事实。
3. 保存事实、来源、事件日期、状态、版本及768维本地向量。候选24小时后在访问/提取时清理；预约类事件日期后31天退出检索但仍可查看删除，一般历史经历不按此规则过期。
4. 纠正/确认/删除使用所属身份和版本校验；变更递增epoch，清理相关历史并撤销旧在途回复。删除原文/向量，不保存文本修订副本；动作元数据及用户盐指纹防止自动重新提取。手动重加并确认是重新授权。
5. 成长开启时，聊天产生的候选与积分同一事务提交，任一步失败不保存本轮历史/候选/积分。

## 检索与上下文（legacy历史路径）

以下保留旧legacy路径的功能说明；当前默认semantic见本页“多语言语义理解”。`memory_routing.py`先检查授权、明确拒绝、近期上下文是否足够；普通问候/知识问题不查库。只有跨会话事实需求才检索；含糊时可用模型路由，低置信/结构错误/超时按不检索处理，不先读库再决定。

路由结构示例（合成）：

```json
{"need_memory":true,"query":"玩家此前的面试安排","reason":"personal_history_needed","confidence":0.9}
```

Pydantic拒绝额外字段；需要检索时query须非空且reason一致；模型置信度至少0.7才采用。旧legacy路径使用查询归一化/扩展、向量与词面混合检索及重排；姓名专门路由，无答案证据准入，来源见`memory_query.py`、`memory.py`。这些属于启发式，不是全语义理解。

只将相关、已确认、有效记忆的id/fact/event_date放入生成上下文。事件日期不等于玩家讲述日期：可以说“我记得”，不能仅凭旧记忆说“你刚才告诉我”。地点使用证据完整名称或代词，不擅自缩写。最新玩家纠正优先，助手历史不能证明玩家事实。

## 框架与接口

SQLAlchemy + PostgreSQL/pgvector；SQLite支持离线/本地验证。实现入口：`app/memory.py`、`memory_query.py`、`memory_routing.py`、`memory_source.py`；网页`MemoryPane.tsx`。

| 接口 | 行为 |
| --- | --- |
| `GET/POST /v1/memories` | 查看/手动候选 |
| `PATCH /v1/memories/{id}` | 带version纠正/确认/处理冲突 |
| `DELETE /v1/memories/{id}?version=...` | 带版本删除 |
| `DELETE /v1/memories` | 清空记忆 |
| `PATCH /v1/settings` | 记忆授权及有效时区 |

写操作需同源、Cookie归属和CSRF；跨身份拒绝。没有外部记忆缓存/后台提取队列；另一窗口已显示文字需刷新清除。账户联系方式不自动变成记忆。

## 多语言语义理解（本轮开发，2026-11-11）

默认`MEMORY_UNDERSTANDING_MODE=semantic`。中文和日语共用`app/memory_understanding.py`的Prompt及严格结构化协议，替换此路径的语言规则路由、自动候选提取、日期短语分类和证据兼容判断；旧`legacy`保留给明确配置的历史回放，不是错误降级。不是把项目所有正则删掉，也不替换权限/字段/证据/事务的程序校验。

### 数据流与结构

1. 未解锁30或未授权：不调用理解工具、不读长期记忆。已授权的每轮先用本轮原文、最多最近12条短期消息、用户IANA时区和程序计算的当地today作一次结构化理解；不先读取记忆库。
2. 结构包含`memory_use`（allow/decline/uncertain）、`need_memory/query/reason/confidence`、`target_slots`类型提示和最多3个候选。普通问候、当前/近期信息足够时`need_memory=false`；拒绝/不确定、低置信、错误结构、超时/503则不检索、不自动提候选，普通回复仍继续，不重试或回退中文正则猜测。
3. 只有need=true才按本人/角色/确认/有效期过滤库，用现有字符向量和词面数值排序召回最多20条。新路径不使用中文姓名/否定/时间的词面兼容规则，不使用旧中文规则扩展查询别名（模型可给出有限相关多语言检索词）；`target_slots`由模型提出固定类型提示，程序按元数据字段召回（含旧name/city/预约枚举兼容），不以中文姓名词面匹配；例如“私は葵です”与“名前”无共同词仍可进入语义选择。旧索引不重建，B01语义嵌入仍未解决。
4. 第二次结构化语义选择只看限定候选的id/fact/event_date及必要近期对话；无答案可选空集。程序检查白名单ID、重复、最多5条/1200字符；不因分数相近自动当答案。首次理解和选择共用默认4秒预算，最多2次分析，无自动重试。
5. 候选只绑定本轮唯一出现的连续原文（1–300 Unicode字符），不翻译/改写。程序只接收高置信的本人明确陈述；他人/引用/假设/不明确主体丢弃。正确源引用不证明语义正确，仍须玩家核对后逐条确认。只有最终回复成功，候选与成长积分才共同提交；撤回/epoch变化撤销旧结果。

合成协议示例（不是实测模型输出）：

```json
{
  "memory_use":"allow","need_memory":false,"query":"","target_slots":[],
  "reason":"no_cross_session_need","confidence":0.95,
  "candidates":[{
    "source_text":"来週火曜日に面接があります。",
    "subject":"user","actuality":"asserted","category":"event","slot":"appointment","confidence":0.95,
    "date":{"kind":"weekday","expression":"来週火曜日","absolute":null,"days":null,"week_offset":1,"weekday":1}
  }]
}
```

### 日期与原文

模型只分类日期关系，程序按本条消息的当地today计算：`relative_days`（明天/明日=+1、后天/明後日=+2）、`weekday`（下周二/来週火曜日=下一周星期二，周一=0）、明确年月日的`absolute`；缺年、只说火曜日、来月/周末、范围或不确定为unknown/null。日期expression必须在候选原文中，字段组合/数值/ISO格式必须合法；这些只检查结构和运算，不能证明模型把短语解释对了。

例：today=2026-11-11、Asia/Tokyo时，上例解析2026-11-17，确认时不重新解释相对日期。相同“明日、面接です。”在不同当天可提出不同日期的新候选，不覆盖旧确认事实；删除撤销指纹仍保守阻止原文自动复活，显式手动重加才重新授权。预约类在日期后31天退出检索，仍可查看删除；普通历史不套用此预约过期。

手动添加/原文修正也发给当前模型分析元数据（不读旧记忆、不检索），源必须覆盖整段手动文字；无法理解时仍保存待确认原文但日期未知，不用正则补猜。确认未修改内容时不额外调用或改旧日期。身份/CSRF/版本/归属先检查，await后epoch再检查；任何确认/替换仍由玩家发起。不同独立预约不凭粗分类强行覆盖。

### 配置、成本与验证边界

`MEMORY_UNDERSTANDING_TIMEOUT_SECONDS=4`（0.1–10）为聊天理解/选择共享上限；手动操作最多1次同样预算的元数据分析。初次理解每个已授权轮次可能多一次调用，即使最后不查库；和原来只在部分含糊句调用模型的路由相比，成本/延迟可能上升。模型置信度0.8是程序阈值，不是校准过的80%准确率。无可用语义提供方（包括普通mock）时跳过自动记忆，手动原文保存仍可用；测试使用显式注入的合成结构结果和MockTransport。

旧回归通过tests/conftest.py显式锁定legacy；新tests/multilingual_memory显式semantic/companion/growth=true并覆盖SQLite/独立临时PG。旧根目录参考/标签、封存v1/v2和源绑定Prompt不变，它们不验收这套新政策。命令与数量唯一记在[测试记录](TEST_HISTORY.md)，中日真实抽取/主体/时间/检索选择质量、幻觉/漏检及成本仍未验收。B02仍可能遗漏、B03不变，M6未开始。

重要旧事查询即使无证据也根据语义计划进入事实核对，不依赖中文词面；记忆分析失败不会自行终止生成，但原有生成或重要事实审查的服务错误仍会返回繁忙提示，不保证所有请求200。记忆分析的最多2次不包括原有生成/审查调用。手动元数据理解前也检查资格/当前授权/epoch；生成Prompt明确旧相对日期不能按今天重新计算，只用已保存event_date，未知不猜。

semantic去重比较原文和事件日期；同一姓名/住址等字段的不同原文须明确替换或独立保留，不因去标点而吞掉候选。删除防复活指纹仍保守保留。PR #31已完成命令行审阅修复，结果见测试记录。
