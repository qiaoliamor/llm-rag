# M2 长期记忆与检索：实现与测试记录

日期：2026-10-31（Asia/Tokyo）。本次实现持久化记忆、混合检索及网页记忆管理。仅使用合成经历测试，不将真实用户聊天、数据库、凭据或原始运行日志提交到仓库。

## 1. 交付内容

- PostgreSQL + pgvector 本地容器、初始化 schema v1 与时区元数据升级v2、版本登记与独立临时库测试脚本；保留无 Docker 的 SQLite 模式。
- 持久化随机浏览器身份，默认关闭长期记忆；开启后提取保守候选，全部逐条确认。
- 候选来源 ID、主体约束、类别、规则默认重要度、置信度（未校准）、事件日期、时区、版本及过期策略。
- 已确认记忆跨新对话和服务重启保留；只对当前身份、当前角色、有效确认记忆检索。
- 本地特征向量、限定同义词查询扩展、pgvector 精确余弦检索、关键词融合、时效/重要度重排及上下文预算。
- 网页支持开启/关闭、手动候选、确认、纠正、冲突替换或独立保留、单条/全部删除和事件时区。
- 网页“计划与进度”直接读取 TODOLIST.md 与 docs/PLAN.md，解决项目进展不易找到的问题。
- Gemini 默认模型和模板统一为本地已验证的 `gemini-3.5-flash-lite`，不覆盖用户已有密钥。

## 3. 本机 PostgreSQL 与真实模型链路

Docker Desktop 启动后，项目专用 PostgreSQL/pgvector 容器健康；数据库只绑定本机端口 54329，数据保留在专用本地卷。随机数据库凭据仅写入被忽略的 `.env`，测试脚本不显示凭据。

独立测试身份使用虚构面试经历，通过真实 Gemini 执行：

1. 开启记忆，聊天生成候选，明确确认。
2. 清空短期对话，再问“下周的求职安排”：检索命中1条，模型正确召回周二的面试；该次请求观察耗时约0.88秒。
3. 纠正为下周三：下次检索命中修正版，模型使用周三。
4. 删除后再询问：检索为空，模型承认不知道安排，没有沿用旧记忆。
5. 最后清空该测试身份记忆并关闭开关。

没有记录费用、每日余额或免费额度；上述一次时延观察不是性能承诺。未运行正式召回率/自然度盲评，不能据此宣称消除幻觉。

## 5. 边界与待完善项

- 当前向量是确定性的本地字符 n-gram/同义词特征哈希，版本 `local-char-ngram-alias-v1`，768维。它不是训练模型生成的深层语义嵌入；陌生同义表达、复杂叙述的召回质量需 M5 评测，后续可替换嵌入模型并重建索引。
- 自动提取是保守规则，只覆盖明确第一人称的重要事件/事实/偏好；引用、假设和他人经历优先不提取。没有覆盖的内容可手动添加；不使用 LLM 猜测经历或真实心情。
- 明天、后天、今天、下周某日与明确年月日可解析；复杂模糊时间保留未知，不补写日期。前端列表展示原文与解析日期。
- 候选24小时过期，访问/提取时清理；面试、考试、手术类未来预约到日期后31天退出检索，仍可查看删除。重要历史经历和一般偏好不按此预约规则过期。
- 身份属于当前浏览器 Cookie，非正式账号系统；清除 Cookie 后无法自动恢复原身份。仍按单 Uvicorn worker 使用；SQLite 仅用于本地单进程/离线验证。
- 删除时清除原文/向量，保留不含文本的修订动作和用户盐指纹以阻止自动复活；不等同于加密或匿名化。Docker 卷未增加应用级加密；备份擦除、账户恢复和完整账号删除在后续发布阶段处理。
- 没有外部记忆缓存或后台提取队列；同步候选、数据库事务和 epoch 失效检查减少竞态。跨进程短期历史在下一次访问时校验 epoch；已显示在另一标签页的旧文本需刷新才能消失。

复现：先按 README 构建；运行 `uv run --frozen pytest -q`、`npm run test --prefix frontend`。实际 PG 测试先运行 `./scripts/setup-memory-db.sh`，再运行 `uv run --frozen python scripts/test_postgres.py`，脚本创建并删除专用临时库，不使用真实记忆库作为测试目标。
