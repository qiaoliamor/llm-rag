## 2. 繁忙时的网页行为

提示区统一使用固定文案：

> 这会儿连接有点慢，先别急，等一会儿再发给我，好吗？

这是服务状态提示，不是沈砚生成的新台词或虚构人物经历。它不写入聊天历史，不生成长期记忆候选，不在回答气泡中伪装正常回答。网页恢复原输入草稿和既有有效历史，由玩家稍后手动点击发送；没有自动重试、后台排队或循环请求，也不承诺恢复时间。

- **审查阶段**：共享预算耗尽/timeout、upstream_unavailable（含HTTP503）、rate_limit、provider_error时，先完成epoch复核，再返回HTTP503，`code=review_busy`及固定安全detail。不放行未审查草稿，首次审查或唯一一次重写后的审查故障均如此。返回发生在候选提取/历史保存之前。
- **生成阶段**：timeout/connection/upstream_error/rate_limit保留原504/502/429等状态与code，聊天接口detail使用上述文案。模型SDK仍零自动重试，原一次重写/共享审查预算不变。
- **网页**：识别上述code及无code的502/503/504、网络连接失败，显示同一文案。密钥/权限/模型配置错误不能一律伪装“繁忙”，仍保留配置指引；409授权撤回仍清除失效历史，优先于繁忙。
- 非暂时故障如非法审查结构、低置信/abstain仍按既有安全回退处理，不新增任意放行或绕过审查。表单/身份/其他设置接口行为不变。

聊天端点及成功字段未重命名，但**审查服务不可用的响应语义改变**：此前200+通用FALLBACK，现在503+review_busy，客户端需要走错误/草稿恢复分支。对原JSON请求的第三方客户端同样生效。错误不显示上游原文、密钥或裁判内部内容，不把服务错误归因于免费额度。

## 3. 回答与审查Prompt设计

优先追加统一规则，没有新增语义匹配正则或扩大旧词面拦截器：

1. 许可内环境、声音、倒茶/整理书等普通动作仍自然展开；具体收货/交易/付款/预约/现实行动、身世关系、玩家位置和共同过去须有直接证据。
2. 逐分句检查主体/时间/因果/预设。“如果”“虽然”“不能确定”只作用于相应分句，不给后半句背书。一个单元有许可氛围但夹带无据事件，整体仍unsupported；不因半句有scene_profile就给全句supported。
3. 到店前提包含释义，如“坐在我对面”“你的外套已挂在这里”“又在店里”，不只匹配“过来”。先到店后离开按最新本人状态；助手旧话不能自证玩家在场。未来邀请、询问是否到店和本人最新到店仍应允许。
4. 最新用户纠正决定当前采用的事实，不代表旧原话未出现；明确引用/批评或撤回的断言不机械当自述。重写仅修无据重要事实/口吻，保留自然氛围。

规则同时进入回答初始与重写上下文（CONVERSATION_FACT_RULES）和审查INDEXED_PROMPT。SDK max_tokens、temperature、传输结构、置信阈值、最多一次重写和每轮共享8秒裁判预算不变；增加规则并不证明误判/延迟改善。
