# M5 检索证据检查与姓名路由修复

日期：2026-11-03（Asia/Tokyo）。基线main为352a5dc（PR #11）；本批任务分支codex/m5-retrieval-evidence-guards。状态：本批修复与开发集评测已实现，M5未整体完成。全部输入、事实和下列真实模型调用的回复均基于原创合成场景，无真实玩家数据；未运行原32个保留案例。

## 1. 复现与原因

原开发集的name-correction需要m01（本人姓名），旧D在身份补入关闭的受控条件下却只取回m03/m16/m04/m19/m10。当前生产原有姓名加分也不能充分区分本人、宠物和他人姓名，且在实验关闭补入时不能靠加分救回未准入的记录。护照无答案会因“我的”等共有词或向量碰撞带入无关事实；童年居住问题会把当前城市当作相关证据。

修复没有全局调高相似度阈值、没有按两个案例ID/错误姓名硬编码，也没有把未知字段一律列为禁止检索。实际问题是对应字段/主体/时间的证据缺失，必须让不存在时返回空、有明确确认事实时仍能召回。

## 2. 实现与边界

新增 [memory_query.py](../app/memory_query.py) 的EvidenceNeed、compatible和正文锚点规则，由 [memory.py](../app/memory.py) 的共享rank_memories调用：

1. 从问题识别有限的主体、字段及时间需求；玩家姓名、朋友/母亲等关系、宠物不能互相替代，角色自身问题不检索玩家个人事实。
2. 本人姓名使用明确第一人称名字事实路由，候选不再依赖与问题预设姓名的字面重合。姓名在相似干扰项之前保留，能够绕过PG纯向量前20的漏选；这个例外只针对已经通过所有权/角色/确认/有效期/嵌入版本过滤的记录，不绕过数据权限。
3. 字段检查只接受对应的明确肯定事实。护照、身份证、电话需匹配相应字段及主体；童年/过去/当前住处要求匹配时间与肯定居住表达，当前城市或朋友童年不能充当本人童年依据。存在受支持的护照事实仍可返回，并非证件信息黑名单。
4. 对没有专门字段规则的普通问题，去除问题支架后需有正文主题锚点。纯共有代词、仅向量碰撞或泛化回忆入口不能在没有证据时强制补齐。普通无特定主题的回忆仍保留已有流程。
5. 生产默认启用identity_routing和evidence_guard，不暴露新API参数，不改schema、授权、角色正史、记忆确认/纠正/删除流程或嵌入版本。持久化向量不重建。

这仍是保守中文规则，不是训练模型语义理解或严格蕴含验证。只覆盖有限字段与明确第一人称/关系、时间表达；复杂引述、反话、跨句指代、嵌套人物、多字段/复合问题、混合时间或未知同义词可能漏召回或误判，不能承诺解决所有无答案问题。后续应按失败集扩展语义评测；不把开发集0次误召回当生产保证。
