# M3 天气工具：实现与命令行测试记录

日期：2026-11-01（Asia/Tokyo）。分支 `codex/m3-weather-care`，基于已合并的 M2 边界记录 `01daa26`。项目声明版本仍为0.1.0，未创建Release/tag。

## 1. 交付范围

- 独立天气授权（默认关闭）、常用城市搜索/选择/查看/修改/删除、同名城市澄清与临时目的地。
- Open-Meteo与显式mock适配、结构化字段投影、当地日期/时区、当前估计与整日预报分开。
- 600秒公共天气缓存、最多128条、进程限流、5秒请求超时、过期/无结果/非法数据/上游故障提示。
- 天气证据、相关确认记忆与角色正史一起组成模型上下文；不对天气推断心情。设置变更通过epoch在调用模型前、生成后复核，防止在途旧回复继续返回。
- schema v3新增 weather_profiles，保留既有身份与记忆。前端沿用React组件与现有样式，增加“天气关怀”。

API选择、免费许可、上下文JSON格式、字段含义与接口见 [天气设计](WEATHER.md)。无需天气API Key；原有模型密钥不更改。

## 3. 真实天气服务冒烟

通过终端使用公开测试城市 Tokyo：地名搜索返回5个候选，选择日本东京时区的候选后，完成真实城市id解析、一次性SQLite保存设置、明日整日预报和当前天气查询，再删除设置。两种weather状态均为ok，时区均为Asia/Tokyo；工具结果成功进入mock对话生成并标明Open-Meteo。

真实天气HTTP成功不等于真实Gemini生成质量已验证。本次不调用Gemini/OpenAI，不使用或输出模型密钥，不把真实玩家所在地/聊天发给天气服务。报告仅记录公开测试城市和状态，不提交原始API日志、数据库或真实对话。未打开网页逐项测试，前端以jsdom交互、类型检查和构建验证。

## 4. 首轮失败与修正

- 20个历史天气场景仍期待旧“查不到实时天气”文案；M3默认关闭并提供授权提示，因此按新行为更新合成场景预期，并补独立授权/无外查断言。
- 新测试发现“现在天气”中的“在”误当地点前缀，以及mock路径未拒绝URL式城市输入；已修正解析与入口校验并复测。另覆盖常见问号问句、活动内容不发给地名服务、取消查询和缓存有效时间复核。代码复核还补充关闭授权可离线完成、旧在途保存不能撤销删除的回归测试。
- 最初PG连接失败，原因是Docker未运行；启动已有Docker和数据库容器后，在独立临时库完成专项，不操作真实库。
- 沙箱内真实天气请求无法连通；使用获准网络执行同一公开城市冒烟成功，失败不转成虚假天气。
