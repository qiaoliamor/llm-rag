# M5 检索评测与消融实验（开发集）

日期：2026-11-03（Asia/Tokyo）。本批在独立任务分支实现，M5仍在进行中。所有事实、问题和回复均基于仓库原创合成数据，无真实玩家对话或记忆。新增数据集不替换首批100场景，也未运行原32个保留案例。

## 1. 实验要回答什么

在相同文档预处理、查询、可见范围、时钟和上下文预算下，查询扩展、混合检索、重排分别改变了哪些结果？提示来源约束能否改变同一证据下的真实模型回复？这两类问题分开测量：检索用确定性指标，提示用小规模配对生成，不拿mock或提示长度冒充质量提升。

代码入口：[memory.py](../app/memory.py) 的RetrievalPolicy/rank_memories、[retrieval_evaluation.py](../app/retrieval_evaluation.py) 和 [evaluate_retrieval.py](../scripts/evaluate_retrieval.py)。生产MemoryStore仍先检查授权、按玩家/角色/状态/有效期过滤，再调用共享评分函数；没有新增网页/API开关。

## 2. 数据、固定条件与指标

数据为 [retrieval_dev.json](../evaluations/retrieval_dev.json)，版本m5-retrieval-dev-v1：40条记录，其中34条可见、6条不可见（其他玩家/角色、候选、被替代、删除、过期）；24个开发查询，22个有答案、2个无答案，共37个正相关标注，包含多相关记忆、同主题干扰、否定、历史/当前城市和错误前提。按记录ID而非词面标注相关性；所有正相关ID必须指向可见记录。该集由开发者制定，难度、重要度/时效先验和标签有偏，不能视为独立保留集或真实用户分布。

固定时钟2026-11-03T00:00:00（naive UTC，与数据库表示一致）；top-k=5，合并后候选最多20，证据正文总预算1200字符。文档向量与关键词预处理在所有组固定使用当前生产的同义词扩展；只消融查询侧扩展，关闭时向量查询与关键词查询都不扩展。它不是“彻底移除整个系统的同义词处理”。字符哈希仍非训练模型语义嵌入，B01保持未完成。

为隔离排序效应，各消融组统一关闭领域候选补入；C与D先取完全相同的候选池，D只改变顺序。重排使用当前重要度、时效和姓名/城市加分，不是学习型或交叉编码器重排。生产默认仍开启原有领域补入，SQLite无该实验的20候选上限；因此这是共享评分代码的受控实验，不是线上完整检索路径或PostgreSQL性能测试。文档向量与数据库版本未改变；embed(expand=False)只用于查询消融，不得把该向量写入同一版本的持久化索引。

指标：宏Recall@5为22个正查询逐项召回率的平均；微Recall为总命中/37；Precision@5固定分母5（不足5也按5），MRR及分级nDCG@5仅对正查询报告。两个无答案查询单列误召回率，不把无答案的Recall记为1或纳入正查询平均。API或程序失败不能计为成功质量结果。

数据SHA256：`8b6d863b63986b2733ca4b9dfd100be4c8c5dc6b14a941f3806cddb17aa228df`。JSON报告包含组参数、每查询ID/排序、上下文字符数、成对差值、胜/平/负、Git HEAD及dirty标记。命令行实测时尚有未提交工作，dirty=true，HEAD为开发基线2b33825，不冒充已提交的实验版本；本PR将冻结对应代码与数据。各组遍历/池化顺序固定，同分保持稳定顺序。

## 4. 提示约束配对实验

D和E对每个问题使用相同证据及同一用户消息，均保留原角色卡、完整正史和通用来源规则；D把相同证据作为普通候选JSON，E使用memory_prompt和m5-source-boundary-v1，强调错误前提不是确认事实、缺证据不知道、主体/时间不可混用。只对来源提示做增强；两组都不加输出重写或额外评审，避免把检查器贡献算到提示上。E增加约224个提示字符，正文证据预算相同，但提示开销不相同。

Gemini模型 `gemini-3.5-flash-lite`，3个合成问题×D/E×2次=12次请求（6对），12/12完成，无重试或额外模型评审。按问题/重复轮交替D/E顺序。生成沿用供应商默认采样（temperature未显式固定），max_tokens=500；没有共同随机种子、独立盲评或显著性推断。每对均记录证据ID与提示哈希。尚未采集token和实际费用，调用成功不证明免费，不能用字符数推算账单。

## 5. 命令行复现

```bash
# 默认离线，不实例化Settings、不加载.env、不联网或读取真实库
.venv/bin/python scripts/evaluate_retrieval.py

# 显式真实模型对照：只用固定合成探针，最多12次请求
.venv/bin/python scripts/evaluate_retrieval.py --live --live-limit 3 --repeats 2 --max-calls 12

# 可选：仅在本地报告中包含固定合成回复
.venv/bin/python scripts/evaluate_retrieval.py --live --live-limit 3 --repeats 2 --max-calls 12 --include-synthetic-replies
```

运行输出可重定向到/tmp，不把导出加入Git。--live使用后端当前供应商密钥，缺密钥或mock时拒绝；预算不足在请求前拒绝，默认上限12、硬上限18。执行成功退出0表示实验完整，不表示低分实验组达标；发生API错误保留脱敏错误码/失败分母并退出1，异常不打印原始配置或供应商响应。离线输出只含案例ID与结构化指标，默认真实报告也不含回复正文。
