# PR #17 · 虚构书店环境与自然闲聊

日期：2026-11-07。用户明确允许“窗外安静”等闲聊环境描写，并指出店主“不知道店里情况”不符合角色。此为产品边界调整，不是把旧模型误判藏成成功。

## 实施前范围

新增独立characters/shen_yan_scene.json，描述沈砚在店、旧街小巷、木书架、阅读桌、暖灯及轻量环境即兴；保留原角色身份/身世/正史文件。回答、重写、grounding提示和审查提示同步更新，撤销普通店况的“具体近况无法确定”建议。审查得到scene_profile叙事许可，支持虚构氛围时可引用；它不是天气API或真实观测。

不新增正则；保留旧场景词面信号作保守回归。支持并引用scene_profile的氛围片段可经语义审查覆盖旧信号，原role_profile不能单独支持具体事件；角色/天气/情绪硬边界不被许可覆盖。引用ID仍不保证语义分类正确，具体收货、消息、玩家到店、现实天气及重要经历不可仅用许可作证。

授权氛围不自动写入长期记忆/正史，不引入场景状态数据库。回答模型沿用近期历史，审查最多接收4条助手台词作为虚构氛围连续性语境，不能把助手台词当玩家/真实工具证据。mock无语义裁判，保留保守旧规则；本次主要改善真实模型角色聊天，不虚称离线mock具备语义理解。

## 预先声明的真实预算

只围绕此前店况问题及其错误回复：1次审查历史“具体近况我还不能确定，不过窗外这会儿倒是挺安静的…”（新策略下氛围允许、店主能力否认需纠正）；1次对“你店里今天安静吗？”生成回答；1次审查新回答，最多3次请求、各执行1次、不重试。没有重复姓名、地名、天气或已成功的到店案例，不运行旧32/16批次。若生成失败，不追加新回答审查，总数只会减少。

本地回归覆盖授权氛围不被旧词面规则误杀、具体事件/玩家/真实天气仍受限、重写自然口吻、失败不落草稿、许可ID校验、语境不作玩家证据、既有CRUD隔离与撤回。保留旧严格策略的52例参考集与历史标签，不改标签迎合新策略；旧静态审计今后明确为legacy策略，不能当当前带许可聊天的事实准确率。

实现与结果在下方补记，PR #17保持草稿、不合并。


## 场景底稿与提示设计

新增场景版本1.0（原角色卡仍1.2、四条正史不变），完整内容：

```json
{
  "version": "1.0",
  "world": "栖川旧书店是游戏中的虚构场景，不是玩家所在地的实时观测。",
  "role_context": "沈砚是亲手开店、日常整理和接待的店主；这段聊天里他身处自己的书店，熟悉店内环境，可以直接回应店里是否安静，不是远程查询店况的助手。玩家通过聊天与他交流，不因此默认已经到店。",
  "environment": "书店在栖川旧街的一条小巷旁，有旧木书架、靠窗的阅读桌、暖色台灯，书页与木头带着淡淡的气息。整体节奏舒缓，适合安静翻书和聊天。",
  "improvisation": "允许即兴描写低风险的虚构氛围与日常小动作，例如店里或窗外安静、轻轻的书页声、暖灯下的书桌、随手整理书页。这些是角色扮演的叙事许可，不需要传感器或天气API证明；可自然说“这会儿挺安静，正好陪你聊聊”。不必每轮重复场景，也不向玩家说明正在虚构。",
  "limits": "不授权改写正史、编造亲属身世、具体收货数量/日期/交易、消息记录、玩家经历或到店、共同过去、替玩家完成现实行动；环境描写不能冒充玩家所在地的实况或推导当地气温/降雨。重要事件和现实工具事实仍需相应证据。",
  "continuity": "沿用近期对话已建立的氛围，不无故反转；玩家明确设定的虚构环境变化可自然承接，但不自动变成玩家的现实经历、长期记忆或角色新正史。"
}
```

回答系统提示在原角色卡旁加载这份场景，canon/rag/direct模式一致。把“未知事实自然承认不知道”限定到未授权的具体事实，不能用它回避自己正在经营的虚构书店日常。CONVERSATION_FACT_RULES明确“你身处并熟悉自己的书店”，问店况时直接用氛围和书接话，去掉“需要时只说具体近况不能确定”的旧建议。grounding升级scene-place-v1.2，同步允许低风险氛围，避免末尾提示又反向禁止。重写要求保留温暖氛围，修正角色口吻及重要事实，不把所有场景词都删成能力声明。

审查的INDEXED_PROMPT先区分叙事许可：scene_profile不是传感器，轻量虚构氛围可标assertion/supported并引用它；具体消息、收货、玩家经历/到店、现实天气不能借此作证。审查也要求把店主回避普通环境的能力声明看作role_context不一致；但实际漏检见后文，不能保证遵守提示。对真正未知的具体外部事件仍可谨慎，不因出现“不确定”就一刀切。

证据包新增id=scene_profile、kind=fictional_scene_license。程序没有逐词判断环境真假，也没有加正则：保留的旧场景信号如果被完整、有效的supported片段引用此许可，可不再强制重写；只引用role_profile仍不能绕过旧事实场景守门。角色正史/已有天气/情绪硬检查优先不变。ID存在只保证来源可见，不证明每个命题被许可；错误引用可能放行超范围事件，这是仍依赖模型的边界，不宣称全事实保证。

近期最多4条助手台词单独放入fictional_dialogue_context，仅作已授权氛围延续；与user、memory、天气等证据分离，不因此给助手生成的玩家姓名/现实事实新增证据ID。场景底稿是代码仓库中的作者设定，不是玩家数据库；本次不提供编辑/删除该底稿的网页CRUD，修改需后续代码PR，不产生新玩家记忆、表或缓存。既有玩家记忆CRUD/删除隔离保持原样。

mock无语义判断能力，保留词面保守路径；真实模型经许可审查才实现本次放行。guarded原字段表示出现保护信号，不能单凭true认定重写，应结合semantic_review.status/calls判断。

## 命令行验证

`.venv/bin/python -m pytest -q`：**602通过/26跳过**，新增16项回归；`.venv/bin/python scripts/test_postgres.py`：**173通过**，独立随机临时库自动删除，与默认重叠不相加。全量第一次599/26是在增加3项CLI预算/legacy标签回归前的结果，最终版本602/26。初次受影响套件186通过/2失败：一个测试把无工具天气的旧表达检查错误当作全面的天气断言检测，另一个Markdown精确断言因新免责声明措辞变化失败。前者改为验证已有工具温度边界并另测无工具天气的语义拒绝路径，后者保留明确“不是自动语义裁判”说明，未删掉失败内容或添加新正则。

回归包含：许可氛围单次生成不重写；角色卡/场景版本及三个提示模式；具体收货/未收到消息/无据玩家到店/不知店况等经有效reject后重写；坏草稿不入历史；正史与已有工具天气硬约束不被许可覆盖；裁判超时不放行草稿；有界助手语境与非玩家证据；显式--live、3次上限及生成失败跳过后审查。假标签只验证协议/控制流，不当模型语义准确率。既有候选确认、查看、纠正、删除、跨玩家/重启隔离及epoch撤回在SQLite/独立PG继续通过。

无工具天气检查不是通用断言检测，若模型把现实气温误判为许可氛围，仍可能漏过；同理错误引用scene_profile不能被程序自动证明不蕴含。保留为独立语义/权限范围评测事项，不声称消除所有幻觉。前端未改，不重跑既有前端36项/构建，不逐个打开网页；原32保留例未执行。

`scripts/evaluate_fact_support.py`仍审计52条旧严格场景参考标注（SHA未变），数值仍TP14/FP5/FN15/TN17及1未决。新增scene_policy=legacy-strict-no-fiction-license和醒目免责声明，禁止把这些旧氛围标签拿来评价当前获授权角色扮演。它只运行原词面检测、不调用当前在线语义审查，既不伪造新通过率，也不改旧标签迎合产品决策；新策略正式独立参考集仍待建设。
