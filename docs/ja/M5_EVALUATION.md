## オンライン判定と構造

必要時の記憶検索後、companion／reply_pipeline／semantic_reviewが重要事実と人物の口調を確認します。通常の挨拶や許可された光・音・普通の仕草を毎回監査しません。正史や本人の経験、出所時刻、地名、到店前提、現実の天気は守ります。場面の雰囲気は取引や本人の経験の証拠にはなりません。

入力は返答の順番付きunitsと、必要な本人発言、正史、scene_profile、確認記憶、今回の有効天気／気持ちです。助手履歴は本人の事実を証明しません。IndexedReviewでconfidence／role_issues／unitsを返し、各unitはid／kind／verdict／evidence_idsだけを持ちます。原文の自由な再出力や思考説明は要求しません。

型、ID、順番、全文の範囲、証拠と判定の組合せを検証し、元の断片へ再構成します。証拠IDの存在は意味的な裏付けの保証ではありません。事実軸と役柄軸を分け、最大1回だけ書き直します。既定の判定共有予算8秒、ルート4秒、SDK自動再試行0。失敗／低信頼／不明をacceptにせず、重要草稿は未確認のまま公開しません。

日本語生成には新しい固定指示がありますが、日本語の複雑な事実を選択入口や中国語中心の局所防線がすべて検出するとは限りません。Promptと構造化の意味判定を優先し、日本語正反対例で漏検／誤阻止を確認する必要があります。

## 開発用資料と独立性

- 検索の拡張／混合／再順位付けの制御実験を実装済み。修復後F方式は37/37、14/14の関連記憶命中、回答なし0/2、0/8の誤検索。作者の開発集に限る値です。
- 旧52例の全文事実監査は15漏検、5誤阻止、1未決を保持します。38例／34出所の参照チェックは実装者の再確認と表面候補であり、独立意味判定ではありません。
- 8組16返信の事実／役柄正反対例、公開24候補と作者草稿、封存v1/v2を保持します。v2はs03の歴史発言否定の曖昧さを改訂しましたが、v1は変更しません。
- 公開・作者既読の24候補はキャリブレーション用です。旧32例は静的な確認で既読となり、完全な未見集ではありません。入替、言語翻訳、別評審、ランダム化だけで独立集に変わりません。

## 人による作業と順番

実装／Prompt調整に参加していない保管者・作成者が、開発者から見えない新正式集を作ります。最低120新場面、六分類各20を下限とし、各指標の分母は別途満たします。独立したA/Bアノテーターが相談せず採点し、第三者が争点を裁定します。保管者は採点しません。現時点で担当者・引継ぎ・実2名による結果はありません。

事前基準→新資料と重複／証拠確認→データと参考ハッシュ→モデル／コード／Prompt／役柄／ツール／日時／予算固定→一度の実行→独立ブラインド採点固定→裁定→開示集計の順です。名前変更や同じ出来事の言い換えは別の独立族にしません。同一意味群を開発と正式にまたがせず、露出・改訂は新版へ残します。開示後に低評価を削除したり成功まで再生成したりしません。

最小命題に分けて全返信をカバーし、Unicodeのstart/end/text（左閉右開）、kind、verdict、証拠、理由、事実／口調軸、応答義務、未決と自然さ／役柄／気遣い1〜5を記録します。問いの前提、引用・否定、混合文、記憶の出所時刻も対象です。候補のモデル・群・判定器結果を隠しますが文体による露出の限界は記録します。

## オフラインの採点ツール

```sh
.venv/bin/python scripts/check_sealed_evaluation.py --validate-content
.venv/bin/python scripts/check_sealed_evaluation.py --prepare-annotation /tmp/m5-annotation-session
.venv/bin/python scripts/score_annotations.py \
  --mapping /tmp/m5-annotation-session/custodian_mapping.json \
  --rater-a /tmp/m5-annotation-session/rater_a.json \
  --rater-b /tmp/m5-annotation-session/rater_b.json \
  --output /tmp/m5-annotation-summary.json
```

保存先はリポジトリ外の新規パスのみで、上書きと一部失敗の残留を拒否します。入力は読み取り専用。各提出は24件すべて必要で、重複JSONキー／タスク、範囲の隙間・重複、証拠ID、凍結結合、点数を検査します。評価原本・対応表・個人情報はGitへ出しません。

不一致は軸、断片、証拠集合、未回答、主観差2以上、関心NA等を列挙します。原一致率とCohen κを分け、主観1〜5は線形重み付きκ（差abs(a-b)/4）を用います。未決／NA／欠落は分母と理由を報告し、退化・単独評審はκ=nullです。一致は正確さや独立性の認証ではなく、作者草稿も正解として使いません。

終了0は入力検証と計算の成功だけ、不正入力は2、現在の未受入キャリブレーションを--require-acceptance付きで出した場合は3です。公開候補、人数・資料不足、独立性未確認、未裁定はnot_assessedのままです。

## 正規表現とPromptの役割分担

すべての正規表現をPromptへ一括置換しません。今回の新既定経路は記憶意図、本人／引用／仮定、候補抽出、日付関係、根拠選択を多言語Prompt＋厳密な構造へ移します。旧memory_routing/describe/extract_candidates/memory_queryは明示legacy再現用で、失敗代替ではありません。

本人権限、CSRF、個別確定、epoch、version、原子取引、削除非復活はプログラムが守ります。ISOや数値、原文／証拠ID、予算、固定URL、文字ベクトル／指紋も決定的な検査として残します。返答入口・正史・天気／気持ち・出所／地名の旧言語ルールは今回すべて除去したわけではなく、普通の挨拶と事実／許可を壊さず次段階で版管理します。

構造・高信頼は意味の正しさの保証ではありません。新memory_understanding/main/memory/progression/reply_pipeline/configとモデルを別途固定し、旧封存／参照を変更せず独立評価が必要です。今回の合成SDK／ライフサイクル検証はモデル品質や新金標準を意味しません。
