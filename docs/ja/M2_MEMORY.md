# M2 · 長期記憶と必要時の検索

[中文](../M2_MEMORY.md) · [日本語](M2_MEMORY.md)

## 機能・設計

親密度30と個別許可の両方が必要です。大切な事実を候補にし、本人が一つずつ確認したものだけを検索します。手動追加・確認・修正・削除も可能です。オフにしても削除はでき、オフと全削除は別の操作です。

所属・versionとepochで更新を守ります。許可変更や修正・削除は古い短期文脈と処理中応答を無効化します。削除は原文／ベクトルを除去し、非テキストの取り消し指紋で自動復活を防ぎます。本人の明示的な再追加は新しい許可です。候補は24時間後、アクセス時に削除します。予定型の記憶は出来事の日付後31日で検索から外れますが確認・削除できます。

必要性ルーターは検索前に許可、拒否、現在の文脈を確認します。普通の挨拶／一般知識は検索しません。不明瞭な需要は構造化モデル判定を使えますが、低信頼・失敗なら検索しません。query、reason、confidence、need_memoryの整合を検査します。

## 実装・API

app/memory.py／memory_query.py／memory_routing.py／memory_source.py。SQLAlchemy、PG/pgvectorまたはSQLite。記憶のid/fact/event_dateだけを必要時に注入し、日付から「さっき言った」と推測しません。本人の最新訂正が優先で、助手履歴は本人の証拠ではありません。

GET/POST /v1/memories、PATCH/DELETE /v1/memories/{id}、DELETE /v1/memories、PATCH /v1/settings。書き込みに本人Cookie、CSRF、versionを使います。成長が有効なら候補記憶とポイントを同じトランザクションで保存します。
