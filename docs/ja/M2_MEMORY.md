# M2 · 長期記憶と必要時の検索

[中文](../M2_MEMORY.md) · [日本語](M2_MEMORY.md)

## 機能・設計

親密度30と個別許可の両方が必要です。大切な事実を候補にし、本人が一つずつ確認したものだけを検索します。手動追加・確認・修正・削除も可能です。オフにしても削除はでき、オフと全削除は別の操作です。

所属・versionとepochで更新を守ります。許可変更や修正・削除は古い短期文脈と処理中応答を無効化します。削除は原文／ベクトルを除去し、非テキストの取り消し指紋で自動復活を防ぎます。本人の明示的な再追加は新しい許可です。候補は24時間後、アクセス時に削除します。予定型の記憶は出来事の日付後31日で検索から外れますが確認・削除できます。

以下は旧legacy経路です。現在の既定semanticは後述します。必要性ルーターは検索前に許可、拒否、現在の文脈を確認します。普通の挨拶／一般知識は検索しません。不明瞭な需要は構造化モデル判定を使えますが、低信頼・失敗なら検索しません。query、reason、confidence、need_memoryの整合を検査します。

## 実装・API

app/memory.py／memory_query.py／memory_routing.py／memory_source.py。SQLAlchemy、PG/pgvectorまたはSQLite。記憶のid/fact/event_dateだけを必要時に注入し、日付から「さっき言った」と推測しません。本人の最新訂正が優先で、助手履歴は本人の証拠ではありません。

GET/POST /v1/memories、PATCH/DELETE /v1/memories/{id}、DELETE /v1/memories、PATCH /v1/settings。書き込みに本人Cookie、CSRF、versionを使います。成長が有効なら候補記憶とポイントを同じトランザクションで保存します。

## 多言語の意味理解（2026-11-11）

既定のMEMORY_UNDERSTANDING_MODE=semanticでは、中国語・日本語で同じapp/memory_understanding.pyのPromptと構造化契約を使います。記憶ルート、自動候補抽出、日付表現の分類、根拠の適合判断を言語別ルールから移します。legacyは明示した過去再現用で、失敗時の代替ではありません。権限・型・引用・確定・取引の検査はプログラムに残します。

1. 親密度30と個別許可を先に確認。無効ならモデルもDB検索も呼びません。
2. 許可後の各ターンで、今回原文、最大12件の短期メッセージ、本人IANA時区、プログラムの当地todayをモデルへ渡します。先にDBを読みません。memory_use、need_memory、query、reason、confidence、target_slotsと最大3候補を構造化します。
3. 挨拶／現在の情報で足りる場合は検索せず、拒否・不明・低信頼・形式失敗・timeout等も検索／自動候補なしで会話を続けます。再試行も中国語正規表現への代替もありません。
4. need=trueのときだけ、本人／役柄／確認済／有効期間で限定した文字特徴と数値の候補を最大20件取得します。新経路は中国語の氏名・否定・時間の語面適合ルールを使いません。target_slotsはモデルが出す固定型ヒントで、既存name/city/予定列挙も互換対応します。「私は葵です」と「名前」に共通語がなくても候補にでき、最終的な意味選択は別に行います。旧インデックス再構築や学習済み意味埋め込みの導入ではありません。
5. もう1回の意味選択で候補id/fact/event_dateと必要文脈から最大5件を選びます。IDの白名单・重複・1200文字予算はプログラムで検査し、回答がなければ空集合です。理解と選択は既定4秒を共有し、分析は最大2回、自動再試行なしです。

候補のsource_textは今回原文に1回だけ出る連続1〜300 Unicode文字で、翻訳／要約しません。subject=user／actuality=asserted／十分な信頼度だけ採用し、他人・引用・仮定・不明は自動保存候補にしません。原文の一致だけで意味の正しさは証明できず、本人の個別確認が必要です。返答成功後にだけポイントと候補を同一取引で保存し、epoch変更なら取り消します。

### 日付と手動操作

意味モデルは関係を分類し、プログラムが当地todayから計算します。明日／明天はrelative_days=1、明後日／后天は2、来週火曜日／下周二はweekdayでweek_offset=1、weekday=1（月曜=0）。年月日が明確ならabsolute、来月・週末・単独の火曜日・年不足・範囲・不確実はunknown/nullです。原文中のexpression、組合せ／範囲／ISO形式を検査しますが、モデルの読み取り自体は保証しません。

2026-11-11、Asia/Tokyoなら来週火曜日は2026-11-17です。確認で相対日付を再計算しません。別の日に同じ「明日、面接です。」を話したら新日付の候補を出せますが、旧確認事実を上書きしません。削除後は保守的な原文指紋で自動復活を止め、明示的手動再追加が必要です。予定型は日付後31日で検索から外れ、閲覧／削除は可能です。

手動追加／原文修正も現在モデルに全原文を送り、日付等のメタデータを解析します。旧記憶は検索しません。失敗時も待確認の原文は保存できますが日付は不明です。変更なしの確認では追加解析しません。CSRF／ID／versionを先に確認し、待機後epochを再確認します。

### 費用と検証

MEMORY_UNDERSTANDING_TIMEOUT_SECONDS=4が共有上限です。手動解析は最大1回。許可した各ターンに追加の意味理解があり、DB検索しなくても従来より呼出／遅延が増える可能性があります。0.8は採用閾値で校正済み確率ではありません。通常mockに意味提供者がなければ自動記憶なし、手動原文保存は使えます。

新しい合成テストはsemantic/companion/growth=trueとSQLite／独立一時PG、SDK境界はMockTransportを使います。旧回帰はlegacyへ固定し、旧参照／封存v1/v2は変えません。実モデルの意味・抽出・日付／主体・選択の正確さ、B01/B02/B03、費用と独立評価は未受入です。結果は[共通テスト](TEST_HISTORY.md)、正規表現の範囲は[M5](M5_EVALUATION.md)を参照してください。

重要な過去の質問は根拠が空でも意味計画から事実チェックへ入り、中国語の語面に依存しません。記憶解析失敗だけで生成を止めませんが、元の生成／重要判定のサービス失敗は混雑表示になり得ます。記憶分析の最大2回は生成／判定の呼出を含みません。手動解析の前にも資格・現在許可・epochを検査し、生成Promptは旧相対日付を今から再計算せず保存event_dateだけを使い、不明を補いません。
