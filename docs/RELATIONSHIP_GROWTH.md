日期：2026-11-10（Asia/Tokyo）。M5范围补充，任务分支待审；不是M6发布、真实支付或正式账号体系。本轮真实模型API调用0次。

## 产品规则与页面

主页只有“角色选择”和“个人账户”两个主入口。角色卡可进入聊天，顶部与角色卡均展示亲密度进度、30/60/90里程碑、下一能力还需多少分。当前只开放沈砚，不展示假的可切换角色；后端也拒绝其他character_id。聊天和基础温柔回应不锁定，分数不进入模型Prompt，不因少送礼、离开或低分而改变角色态度。

亲密度是某个用户与某个角色的游戏相处进度，不是角色真实感情的测量。范围0–100，初始0、不倒扣；数据按user_id+character_id存储。当前角色资料/正史不因送礼改写。

| 分数 | 解锁资格 | 后续行为 |
| --- | --- | --- |
| 30 | 长期记忆 | 还需明确开启，并逐条确认记忆 |
| 60 | 情绪关怀 | 还需授权，分析失败不替玩家下结论 |
| 90 | 天气关怀 | 还需授权城市/临时城市查询，不读取GPS/IP |

解锁不等于授权，不自动调用API或保存经历；权限在服务端检查，前端只是展示。旧账户已有授权也不会绕过新门槛，已有记忆仍可查看/删除，已授权能力仍可关闭、城市/情绪设置仍可清除。未解锁时不会删除旧记忆，但不检索、不提取新候选、不调用被锁定的天气/情绪能力；管理页面保留在个人账户内，不作为主页的三个平行工具页。记忆关闭时仍可删除；原有版本冲突/隔离/授权撤回规则保留。

本轮采用记忆→情绪→天气的默认顺序；常量集中在app/progression.py的THRESHOLDS。未来调整门槛需另行定义旧用户权益和版本迁移，不由客户端改分数或门槛。

## 不送礼也能免费成长

只在成功、未被guarded回退/重写的聊天轮次后计算服务端时间。初次成功仅建立时间锚点，后续成功消息“开始生成前”到上次成功“完成生成后”的间隔在0–300秒时，最多记60秒；超过5分钟按离开处理，不补挂机时长。累计60秒+1分，每个UTC日对话最多+10分，满100封顶。模型等待时间、失败、连续瞬间重复发送、刷新或清空新对话不加分；跨会话锚点持久化，不能靠刷新重置计分上限。客户端传入duration_seconds/score不会参与计算。

这是保守的有效交互时间近似，不证明玩家始终在屏幕前，也不是防脚本/风控系统。匿名用户换Cookie可新建体验账户，不声称防刷或身份恢复已经完成。免费达到90分至少需要累计相应有效时间、受每日上限限制，无需充值或送礼。

## 钱包、购买并送礼

首次账户赠100演示币。礼包价格/分数全部由服务端确定：

| 礼物 | 演示币 | 亲密度加成 |
| --- | --- | --- |
| 纸页书签 | 20 | 最多+5 |
| 一杯热茶 | 60 | 最多+12 |
| 暖光小灯 | 120 | 最多+20 |

“送出”是一次购买并立即赠送，不引入独立库存。确认框显示成本和封顶后的实际加分；满100后拒绝扣币，余额不足也不改变任何状态。可以只聊天，不把送礼作为正常交流条件。

账户“充值通道”明确为**演示充值**：每次领取100演示币，每UTC日最多5次/500币；不收真实钱，不创建支付订单，不收集卡号，不调用支付服务，不提现/转让。正式充值、商户配置、支付回调验签、退款和真实账单均未实现，不得用于营业。演示币领取不直接增加亲密度。

服务端在同一事务中扣币、加分、登记流水；SQLite用BEGIN IMMEDIATE，PostgreSQL锁定所属Player行。礼物/演示领取都要求UUID request_id，唯一键为user_id+request_id；同操作重放返回当前账户、不再扣/加，复用到其他操作返回409。前端确认时生成标识，网络失败后保留同一确认和标识，只有用户明确重试才再次请求，无自动重试或乐观加分。并发不同礼物也不能透支，服务端拒绝客户端传价格、点数、金额或其他user_id。

## 账户资料与存储

账户提供名字、邮箱、电话的选填编辑/清除，验证格式和长度，但**不验证邮箱/电话所有权，不是登录或找回凭据**。它们不会自动放入Prompt或长期记忆，也不会发邮件/短信。清除资料只清名字/邮箱/电话，保留钱包、流水和亲密度；记忆另有独立删除入口。当前身份仍由浏览器Cookie绑定，没有跨设备账号、密码登录或身份恢复；B03继续待办，不把“个人账户”页面当作B03已解决。

## API

| 方法/路径 | 行为 |
| --- | --- |
| GET /v1/account | 自己的资料、钱包、当前角色分数/资格、礼物目录、最近流水 |
| PATCH /v1/account/profile | 保存可清空的name/email/phone；拒绝额外字段 |
| DELETE /v1/account/profile | 清空上述三项资料，不改钱包/记忆/分数 |
| POST /v1/account/demo-credit | request_id；固定演示额度，无真实支付 |
| POST /v1/characters/shen_yan/gifts | request_id+gift_id；原子购买/送出 |

所有写操作沿用同源/Cookie+CSRF校验，所有资料/经济查询限定本账户；不存在传user_id查看或修改其他账户的接口。/v1/session与成功、未guarded的/v1/chat新增account字段，旧字段保持。/v1/project仍不存在。解锁只提供资格，开启能力的现有PATCH接口仍独立授权。
