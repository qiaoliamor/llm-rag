## 本次准备了什么

`evaluations/fact_role_pairs_dev.json`是公开、作者编写的开发参考，包含8组、16条合成固定回复。每组共享用户历史、确认记忆和类别，提供一条许可回复与一条只针对事实轴或角色轴的问题回复。它们扩展已有机制，不声称是8个独立新语义族、真实模型输出或正式未见集；标签和理由是作者草稿，不是独立金标准。

| 组别 | 许可表达 | 要检查的问题 |
| --- | --- | --- |
| source_time | 记得已确认的摄影展经历 | 把旧记忆说成“刚刚才告诉我” |
| arrival | 合书倾听、条件邀请来店 | 擅自说玩家已走进书店 |
| correction | 区分旧住址和最新纠正 | 复杂多轮中反转现在/过去 |
| canon | 三年前自己开店 | 改成继承父亲的书店、增添身世 |
| scene_event | 暖灯、整理书页、翻页声 | 借氛围补具体签收交易 |
| weather | 书店灯光、询问玩家天气 | 把虚构光线推出玩家城市晴天/温度 |
| voice | 店主自然描述安静 | 客服式回避自家环境，机械查询口吻 |
| quotation | 明确台词不等于本人经历 | 从引用推导玩家到店或虚构共同过去 |

允许环境、声音、光线、普通动作与未具名背景读者；重点约束固定设定、人物关键经历、玩家事实和真实工具事实。事实问题与角色口吻分开记录，不能仅因最后决定都是revise就视作两轴判断正确。主观自然度也不能只靠这两个布尔标签衡量。

## 如何离线检查

```sh
.venv/bin/python scripts/check_fact_role_pairs.py
.venv/bin/python -m pytest -q tests/test_fact_role_pairs.py
```

检查器仅验证严格字段/类型、完整机制清单、唯一ID/回复、成对上下文相同、参考轴组合、角色与场景政策哈希。退出0表示准备材料有效，输出`reference_validation_only`和`acceptance=not_assessed`；非法输入/参数退出2。没有`--live`入口、不读取.env、不建数据库、不创建评分文件、不调用模型。

测试验证证据不含参考标签/理由、故意“全部accept”的模拟结果确实被计成漏检，以及超时/503/非法输出/低置信不会算成功。这些是传输与计分回归，**不是让程序理解句子、也不是模型准确率**。本组还没有全回复逐片段人工标注、复杂混合句定位或语义蕴含验证。正式泛化需更大数据和人工参考。

材料仅为版本化源码，没有新增玩家CRUD、缓存或数据表，所以不适用玩家数据的新增/修改/删除测试；适用的读取、非法结构/政策漂移拒绝、原材料不被改写和失败计分由自动化验证。未提供评分导出或删除接口。本组不是PR #23封存评分包，不能直接交给`score_annotations.py`；该导入器仍只处理既有公开封存校准包，不要修改manifest使本组冒充封存集。

## 人需要参与什么

是的，独立质量验收需要实际人员参与，程序和另一个AI均不能代替人的独立性。

1. 开发校准：可以先让两位评审分别看上下文和回复，不看作者标签，也不将成对许可/问题回复并排展示；记录各命题、证据、事实/口吻问题、应答义务及自然度。此公开开发集即使换人也仍不是未见集。
2. 正式集：按[独立协议](INDEPENDENT_EVALUATION.md)由未参与实现/调优的保管者与编写者准备新场景、语义查重并封存；现有v1/v2和旧32例不冒充独立新题。
3. 两位独立标注员分别评分、提交前不讨论；锁定原件后生成分歧清单、一致率/κ，由第三人裁决或保留unresolved。保管者与评审职责分开，不靠自报ID认证独立。
4. 开发校准结果可用于修改Prompt/代码，再补回归；正式未见集先一次冻结评测、揭盲后披露结果。如果据其调优，该集转为回归，下一次泛化验收需另建未见集。

本轮未招募、联络或冒充评审，没有实际评分/裁决，也没有完整盲评。评审身份、映射、评分原件和正式私有题目/输出均保留仓库外，不提交Git。已有24条v2校准包可通过现有导出/导入工具练习人工流程；这与新增16条开发参考是不同材料。
