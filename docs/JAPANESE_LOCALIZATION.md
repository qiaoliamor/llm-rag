## 本轮已经实现

- 同一React应用切换中文/日本語，不复制前后端或另建玩家库。默认中文；选择保存在`persona.ui.locale`，只保存语言，不保存聊天/账户/分数；禁用localStorage时仍可用。
- 集中日语词典`frontend/src/locales/ja.json`及`i18n.ts`，覆盖角色选择、聊天、账户、礼物、隐私管理、天气依据、情绪设置、错误和解锁说明；同步HTML lang、标题、日语字体/断行和无障碍标签。繁忙/操作中禁止切换，避免在途请求语言混杂。
- 中文请求仍用原JSON；日语`POST /v1/chat`增加可选`locale:"ja-JP"`，仅允许zh-CN/ja-JP，非法值422。后端固定语言指令不接受客户端自定义Prompt；每次请求选择语言，不影响其他身份。切回中文时在当前会话明确切换。
- `app/localization.py`追加自然日语指令、提供明确标识的日语mock及确定性回退翻译。真实供应商原文照原样交付；不自动翻译旧聊天、玩家姓名/联系方式、记忆/城市/地名，不改角色ID和正史。沈砚显示为沈硯，28岁、栖川开店等事实不变，不据日语UI搬到日本或改身世。
- IME确认Enter不发送，提交后Enter才发送，Shift+Enter换行；继续保留失败草稿、手动重试、同UUID礼物幂等、30记忆/60天气/90情绪、解锁≠授权和既有数据删除入口。
- GitHub入口`README.md`/`README.ja.md`，模块中文在docs根、日语版在docs/ja，互相链接。日语页覆盖当前功能/设计/测试边界；旧原始合成回复、评分协议血缘、封存和权威AGENTS共享单份，不翻译或改写历史证据。以后语义变更同步双语页。

## 为什么日语适配不能只换文案

| 方向 | 当前边界 | 建议改进与验证 |
| --- | --- | --- |
| 口吻/文化 | 已加日语生成指令，但未真实验证自然度 | 日本语母语评审检查敬语/常体、称呼省略、距离感、不过度安慰/自称恋人；保持沈砚性格而非直译“男友模板” |
| 输入/排版 | IME、字体和换行做自动化；无设备实测 | 日文长标签、窄屏、键盘/读屏和不同IME人工抽查，Unicode字符计数/组合表情与前后端长度统一另评估 |
| 记忆提取/时间 | 已实现中日共用语义路由/原文候选/日期运算，失败可手动保存未知日期；真实模型质量未验收 | 独立验证日语候选/主体/否定/引用/纠正/相对日期理解，保持逐条确认；不将未知日期猜成有效日期 |
| 检索 | 768维字符哈希不等于日语语义嵌入；新路径已采用语义类型/选择，旧legacy字段规则偏中文 | 日语分词/表记揺れ/假名汉字、跨中日检索独立开发集；评估多语言嵌入并定义重建索引/迁移，不静默改旧向量版本 |
| 天气 | 已实现中日共用意图/城市/日期结构化语义入口和原文/时区校验；真实理解质量未验收 | 合成覆盖明日/明天、明确周/日期、隐喻/取消、重名、失败和撤回；独立评估城市级判断、否定与日期，不由UI语言改时区或取IP/GPS |
| 情绪 | 本轮新增中日共用自述/否认/变化/请求语义入口；调度由程序保留，模型解释不冒充手动确认 | 独立验证日语省略/委婉/反讽/否定和最新自述优先；低置信unknown、非诊断、手动可纠正；回复检查/兜底已用双语Prompt与locale安全短句；真实口吻、误判及F1未验收 |
| 事实审查 | 本轮默认reply semantic迁移正史/来源时间/地点词面与中文选择入口，真实复杂事实仍可能漏检 | 优先日语生成/审查Prompt和结构化语义入口校准，不逐句堆正则。新增年龄/身世/玩家经历/来源时间/地名/到店预设双轴正反对，独立验证漏检/误拦截 |
| 数据与经济 | 语言切换不换身份/授权/钱包 | 维持原币种语义“デモコイン”，不显示成JPY/真实充值，不按日本语UI切换UTC额度日；正式账号/支付仍未实现 |

当前已包含日语UI、基础对话及中日记忆/天气语义入口，仍不是全面日语质量交付。设置说明模型数据流与限制，不宣称“检测到任意日语地名即可准确关怀”。合成契约只证明实现边界，不证明真实理解精度。
