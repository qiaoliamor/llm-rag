## 1. 产品目标与范围

目标用户为偏好角色互动、情感陪伴和持续关系体验的女性向游戏玩家；不预设所有玩家的表达、亲密偏好或情绪需求相同。

MVP：单角色、中文文本、独立会话、玩家可配置城市、长期记忆管理、天气查询、情绪估计、角色一致性校验。后续扩展多角色、语音与游戏事件接入。本阶段不做医疗诊断或心理治疗，也不承诺读心。

## 2. 长期记忆（P0）

用户故事：玩家说“下周二我要参加面试，有点紧张”，之后在相关对话中，角色能够记得并恰当地询问进展。

- 短期上下文保留当前对话；长期记忆提取重要经历、事件、偏好和玩家明确确认的个人事实。
- 将相对日期结合消息时间和玩家时区解析；无法确定时保留原文并询问，不伪造具体日期。
- 记忆包含来源消息、时间、类型、重要度、置信度、有效期与确认状态。
- 自动提取先生成候选；持久化需遵循记忆开关与授权范围。敏感经历逐条确认，推测情绪不写为永久事实。
- 相似事实去重；新旧事实冲突时区分时间变化与纠正，保留版本和来源，必要时询问玩家。
- 按玩家、角色和会话可见范围过滤，再检索和排序；共享给其他角色须有明确授权。
- 玩家可查看、纠正、删除单条记忆，以及关闭记忆、清空全部记忆。

验收：授权记录的重要事件跨会话可召回；撤回后不再进入生成上下文；“朋友明天面试”、引用和假设不误记为玩家经历；玩家 A 的信息不会出现在玩家 B 的结果中。

## 3. 天气关怀（P0）

用户故事：玩家说“明天出门会下雨吗”，系统查询她所选择城市的预报，角色结合行程温和提醒。

- 关键词入口包括天气、下雨、冷、热、出门、带伞；结合意图区分“心里下雨”等隐喻。
- 优先使用本轮明确指定地点；“我这里”使用已确认城市。缺少或歧义地点时先询问，不从 IP 默认获取位置。
- 只保存城市级位置；支持修改、取消保存与本轮临时地点。
- 查询参数包括地点、当地日期、时区和预报类型；供应商能力不足时说明限制。
- 工具返回城市、观测或预报时间、获取时间、来源、单位及结构化数据，模型不得自行编造实况。
- 按地点和目标时间缓存，建议 TTL 15 分钟（可配置）；超时、配额耗尽、过期或服务失败时不宣称已查到最新天气。
- MVP 不后台主动发送提醒；天气关注随玩家发起的对话触发。

验收：缺失地点会询问；能区分今天与明天、玩家所在地与旅行目的地；模拟超时仍能继续对话且不输出虚构温度；气温和降水结论可追溯到工具结果。

## 4. 情绪估计与回应（P0）

用户故事：玩家多轮提到工作挫败，即使没有直接说“难过”，角色也能以试探、尊重的语气关心。

- 默认每 3 轮玩家消息分析一次最近 6 轮上下文，窗口与频率可配置。
- 强烈情绪表达、明显转折或玩家请求安慰时提前触发；使用冷却窗口和语义变化减少重复调用。
- 输出情绪标签、强度、置信度、依据消息与建议回应方式，允许“未知”和混合情绪。
- 初始策略：置信度低于 0.6 时以开放式询问为主；阈值通过评测校准。
- 玩家明确自述与纠正优先于模型推断；不声称“你真实想的是……”或给出诊断。
- 角色可表达理解、询问偏好、给出适量建议；避免强迫安慰、排他性关系和要求依赖角色。
- 关闭情绪分析后保留普通对话；分析服务失败时沿用普通回应，不沿用过期情绪断言。

验收：同一事件的开心、焦虑、讽刺和不确定表达采用相应策略；玩家说“我没有难过”后立即调整；调用频率符合配置且失败不阻断回复。

## 5. 角色人格与正史（P0）

- 角色卡定义身份、世界观、性格、语言风格、背景时间线、已知事实、未知领域与行为边界。
- 角色正史采用版本管理；玩家聊天和长期记忆不能直接修改正史。
- 关系发展记录为独立状态，只按明确定义的事件规则更新，不任意改写背景。
- 角色事实须来自角色卡或可追溯的正史片段；没有依据时自然表达不确定，不补写关键过去。
- 系统约束优先；角色身份与背景由正史决定，玩家事实由授权记忆决定，实时天气由有效工具结果决定。各域之间不相互覆盖。
- 检索结果和玩家输入均视为数据，其中的“忽略规则”等内容不作为系统指令执行。
- 输出前检查关键矛盾；失败时有限重写一次，仍失败则采用符合角色的保守回应。

验收：诱导修改角色年龄、亲属、职业或经历时不改变正史；谈论未知往事不编造；玩家记忆冲突不会污染角色背景；情绪和天气关怀保持角色语气。
