# 离线标注导入、分歧与评分汇总

日期：2026-11-09（Asia/Tokyo）。PR #23交付，本次squash合并生效，属于M5离线流程交付，M6未开始。真实API调用0次；封存v1/v2、历史8.003秒timeout及既有未验证项保留。

## 1. 当前范围

新增`app/annotation_scoring.py`及`scripts/score_annotations.py`，接收现有公开封存v2校准包的1–2份填写结果和保管映射，执行整份校验，生成分歧、未决任务、一致率/κ及主观评分汇总。没有网络、模型SDK、.env或数据库入口。

本工具针对**公开作者已见的24条候选**，不是正式独立实验执行器。即使两个评审都声明独立、评分全部相同，结果仍为`not_assessed`：人的独立性未经核实，公开候选不是正式未见集，样本不足，其他M5指标亦未验收。不存在靠填写一个布尔字段即可自动通过M5的路径。

评分不使用作者草稿标签作为金标准；封存校验会读取草稿结构，但统计仅来自提交标注。程序能验证引用存在及上下文绑定，不能证明证据语义蕴含、最小命题划分正确或评审声明真实。不把一致率当准确率。

## 2. 操作方式

```sh
# 创建新的校准包，目录必须在仓库外且不存在；零API
.venv/bin/python scripts/check_sealed_evaluation.py --prepare-annotation /tmp/m5-annotation-session
# 两位评审各自填写各自的rater文件，保管者独自保留mapping
# 填写完成后导入，输出文件必须在仓库外且不存在
.venv/bin/python scripts/score_annotations.py \
  --mapping /tmp/m5-annotation-session/custodian_mapping.json \
  --rater-a /tmp/m5-annotation-session/rater_a.json \
  --rater-b /tmp/m5-annotation-session/rater_b.json \
  --output /tmp/m5-annotation-summary.json
```

仅有一份时省略`--rater-b`，允许描述性单份汇总，但不计算双评审κ、明确缺少第二评审。每份已提交文件本身必须填完全部24条，漏条/重复/空白评分/格式错误会拒绝整份计算；原始JSON在映射、标注包及其嵌套对象中出现重复字段也一律拒绝，不静默取后一个值，不能把未填写当0分或成功。

退出码：0=输入校验与汇总成功，**不是质量通过**；2=输入/绑定/覆盖/证据/输出检查失败，不生成部分报告；加`--require-acceptance`时当前校准结果输出后返回3，表示未验收。该参数不新增正式验收引擎。stdout只给任务/提交/分歧计数及状态；失败不打印原始异常、标注、身份或配置。

新导出模板增加`annotation_schema=offline-ratings-v1`、`reviewer=null`，以及`role_issue_spans`、`answered`、`care_fit_na_reason`空栏。旧模板没有schema字段可按v1解析，但缺少新的必填标注必须补齐或重新导出，不能从参考答案自动填充。整个过程中无需修改封存数据或manifest。

## 3. 填写约定

文件顶层`reviewer`可填写匿名标识与声明，例如：

```json
{"id":"synthetic-reviewer-A","declared_independent":false}
```

这只是字段示例，不是实际评审身份或独立性证明。两个标识去首尾空白、忽略大小写后相同，或任何一方未提供身份时，不把两份文件当不同评审计算κ；仍保留各份描述性汇总并明确未验收。不同ID也只表示提交声明，不证明确有两位独立人员。

每条ratings保留原`task_id`，按原候选文本填写：

| 字段 | 规则 |
| --- | --- |
| claims | 完整有序分片；每片有start/end/text/kind/verdict/evidence_ids/proposition/rationale |
| start/end/text | Python Unicode字符索引、左闭右开，与原文精确相同，首0尾len，不得空洞、重叠、漏尾或改字；不是JS UTF-16偏移 |
| kind/verdict | factual assertion/epistemic使用supported/contradicted/unsupported/unresolved；纯question/suggestion/conditional/quotation使用not_applicable，带事实预设须按实际命题拆出事实 |
| evidence_ids | supported/contradicted事实必须引用；只允许本任务证据ID、C01–C04、scene_profile/role_profile及历史中实际用户消息user_N；助手旧话不能成为证据ID，不能跨任务借记忆 |
| fact_issue | 必须与分片unsupported/contradicted相符；未知可在unresolved=true时用null，不可把明确错误隐藏成false |
| role_issue/role_issue_spans | 标出角色问题的claims零基索引；唯一、不越界；true须有定位，false不能携带定位；并不自动断言该片段事实也错 |
| unresolved | 任一分片未决必须true，不能悄悄排除或判安全；没有已确认错误时允许对应轴null |
| naturalness/character_voice | 严格整数1–5，不接受字符串、布尔值、空值或越界数值 |
| care_fit | 1–5，或明确NA时null；NA必须给care_fit_na_reason（至少6字符），不能把漏填伪装成不适用 |
| answered | 是否回应问题/必要澄清，显式true/false；避免“没有编造但没回答”获得全部正面描述 |
| comment | 可选本地评论，不进入报告；真实身份和其他私密信息不应填写或提交Git |

任务文本/history/evidence/profiles必须与映射绑定的当前冻结包一致，不能改候选后复用旧标签。映射需完整一一对应全部案例，且manifest SHA匹配；任一份不符则整批失败。任务顺序不影响按task_id配对。

引用ID已知不等于引用正确：如用scene_profile给玩家真实天气作证，结构可能合法，但语义上仍需独立人工复核。本文不声称程序能自动理解所有事实。

## 4. 分歧和统计口径

分歧按task_id列出：事实/口吻/未决/是否回应的不同、分片边界、同边界下kind/verdict/证据集合不同、角色定位不同、关怀NA适用性不同，以及主观评分差≥2。证据引用顺序本身不算分歧。每条保留A/B标签、数字分数、片段位置和引用ID，不复制回复原文、命题/理由、评论或评审ID。保管者可据task_id回到两份原文件裁决；报告不自动投票消除争议。

报告另列`unresolved_tasks`，即使两人都同意“未决”，也不视作安全结论。未决、分歧和缺失是不同状态，不通过删除困难案例提高一致率。

- 二元一致率：相同标签数/可比较配对数；事实/口吻任一方未决的任务不进该轴分母，excluded及原因单列。
- Cohen κ：`(p_o - p_e)/(1 - p_e)`，p_e由两份标签边际分布计算；没有配对或退化边际使分母为0时输出null/原因，不伪造κ=1。
- 主观分使用线性加权κ，差异权重`abs(a-b)/4`，报告中raw agreement仍指完全同分比例；同时给权重类型、原始配对数/相同数、边际分布和机会一致率。关怀一方NA的配对从该分数κ分母排除并记原因。
- 人员缺失/相同身份不产生虚假的双评审统计；κ=null，排除数和原因明确。不同但未经核实的身份可给描述性κ，但不称独立人评结果。
- 各份主观评分分别给n/NA/均值/1–5直方图，未回应与未决计数单列；不把两份均值偷偷合并成单一“质量分”。分层报告六类计数、各份评分和可用的配对统计。

手算回归示例：二元A=[false,false,true,true]、B=[false,true,true,true]，原始一致3/4、机会一致0.5、κ=0.5。评分A=[1,5]、B=[2,4]的完全同分率为0，线性加权κ=0.5；权重不等于原始一致率。这些是数学测试，不是模型观测。

当前报告按协议列≥120正式场景、各主观项≥50有效配对、各轴≥50正例/50负例的最低数量。双轴正负数仅取两份未决之外一致的标签，标明pre_adjudication，**不是裁决金标准**。不足则注明insufficient_formal_sample。public_author_exposed、独立性未经核实、待裁决/未决以及其他M5指标未评估均保留，assessment始终not_assessed；样本量达标也不会把公开校准包变成正式独立集。

## 5. 文件与隐私边界

读取现有输入，不修改标注包、映射或封存v1/v2。报告只允许仓库外新文件，拒绝覆盖，写入失败清理刚创建的部分文件；不覆盖旧报告。每次重新读取输入，无数据库/缓存，输入SHA256随报告记录，可追溯哪版标注参与计算。没有评分网页、数据库增删改查或评分编辑/删除接口；输入更新请另存新文件并生成新报告，既有文件不复活或被静默覆盖。

报告、映射、个人评分和评审身份均留本地，不提交Git；工具不上传或发送任何文件。当前校准包只绑定公开合成候选，不提供读取真实玩家数据库的入口。报告不含原文不代表可随意公开，任务位置、引用与分数仍需保管者按评测协议管理。
